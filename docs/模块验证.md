## 一期（`output/runs/run_<ts>/`）

| STEP | 作用 | 过关标志 |
|------|------|----------|
| `1.1` | 校验 scenario + 训/评表 | `data_ok.train/eval.ok == true` |
| `1.2` | 正式训练（默认 1500 轮） | `01_train/ppo_rice_best.pth`；回填 `RUN_REL` |
| `1.3` | 全验证年评估 | `02_eval/compare_summary.json` |
| `1.0` | 一键 = 1.1→1.2→1.3 | 同上完整 run |

```text
main.py → STEP = "1.1" → 跑通 → "1.2" → 回填 RUN_REL → "1.3"
# 或直接 STEP = "1.0"
```

### 1.1 校验：训集 / 评集各查什么、怎样才允许训练

读 `configs/scenario.json`，对两套表分别做**同样规则**的日历对齐检查（实现：`common.scenario.validate_scenario_data`）。

| 角色 | scenario 字段 | 默认文件 | 谁用 |
|------|---------------|----------|------|
| **训练集** | `data.forecast` / `data.actual` | `data/forecast.csv` · `actual.csv` | 仅 **1.2 训练**（env 随机抽年） |
| **评估集** | `data.forecast_eval` / `data.actual_eval` | `data/forecast_policy.csv` · `actual_policy.csv` | 仅 **1.3 评估**（及二期 review 滚轨迹） |
| 生育期 | `data.growth_para` | `data/growth_para.csv` | 训、评共用 |

情景日历（须与表一致）：

- `start`（如 `06/15`）：季初日；`reset` 定位起点  
- `terminal`（如 `10/04`）：命中则 episode 结束  
- `duration_days`：应等于 start～terminal **含首尾**天数（当前默认自动算 = **112**）

**合理 / 允许训练的硬条件（任一年不通过则 `ok=false`，不要开训）：**

1. 文件存在，且 forecast / actual **年份集合对齐**（actual 不能缺 forecast 里有的年）。  
2. **每一个年份**，表内日期集合必须 **精确等于** 该年 `start～terminal` 逐日集合：  
   - 不能缺日（缺一天 → 训练中途 `iloc` / 奖励前瞻会炸）  
   - 不能多出季外日期（多一天也会错位）  
3. 展开天数 = `duration_days`（与日历不一致会直接报错）。  
4. `1.1` 要求 **训表 + 评表都 ok**（`need_train` + `need_eval`）；只训不评时底层可只验训表，但正式流水线两边都过才稳。

打印里看：`data_ok.train.ok` / `data_ok.eval.ok`、`n_years`、`bad_years`（空列表才合格）。  
当前规模约：训 **88** 年、评 **8** 年（以你机器上 `show_config` 为准）。

### 1.2 正式训练：干什么、落什么盘

- 新建 `output/runs/run_<时间戳>/`，权重进 `01_train/`。  
- 每局：随机抽一年 → 从 start 滚到 terminal（约 112 天）→ 掩码采样 → `env.step`。  
- 每 `TRAJECTORY_NUM`（默认 10）局做一次 PPO update。  
- **评估/上线只用** `ppo_rice_best.pth`：近窗口（长训约 **100** 轮）回报均值的历史最优；另存 `_last.pth` 作末态对照。  
- 训完回填：`RUN_REL = "output/runs/run_…"`。

#### 终端一行怎么读（示例）

```text
  ★ Best ep=268  近100轮均值=63.303 → 写入 best
[ 268/1500] R= 67.44 mean10= 65.02 mean100= 63.30 days=112 year=2125 irr=22 drn= 7 nz=29 T=0.91 best=63.30@ep268
```

| 字段 | 含义 | 怎样算「训得好 / 正常」 |
|------|------|------------------------|
| `★ Best ep=…` | 近 window 回报均值创新高 → 写入 `*_best.pth` | **主信号**：中前期应较频繁刷 ★；后期变稀但 `best` 分数整体高于开局 |
| `近100轮均值` / `mean100` | 选 best 用的分数；近 100 局回报均值 | **主看**：相对开局明显抬升后走平；长期低于早期或持续下滑 → 变差 |
| `best=…@ep…` | 历史最优窗口均值及出现局号 | 训完后 `best` 应明显高于前 100 局；若一直停在很早的 ep 且分数低 → 几乎没学到 |
| `mean10` | 近 10 局均值 | **辅助**：抖动大正常；若长期远低于 `mean100` 再观察是否崩了 |
| `R` | **单局**回报 | **不要单局论成败**（年际差异大）；看趋势用 mean |
| `[ep/1500]` | 进度 | 信息项 |
| `days` | 本局步数 | **健康检查**：应稳定 ≈112；经常远小于 112 → 提前结束/数据或 env 异常 |
| `year` | 抽到的年 | 信息项（应看到多年轮换） |
| `irr` / `drn` / `nz` | 灌/排/非零动作天数 | **辅助**：开局常偏乱、次数偏多；中后期相对克制更合理。骤升到几乎天天花 → 可疑 |
| `T` | 采样温度 | 应随进度从 ~1.0 → ~0.5；异常卡死不动才需查 |
| `Lπ` / `Lv` / `H` | 策略/价值损失、熵（每 10 局 update） | **辅助**：偶发尖峰可接受；长期爆炸或熵塌到近 0 且回报变差 → 不稳 |

**怎么读（实操优先级）：**

1. **效果好不好 → 先看 `mean100` 与 `best`**：爬升 → 走平；且周期性出现 `★ Best`。  
2. **有没有学「少乱动」→ 再看 `nz`（及 irr/drn）**：相对开局略降、不再瞎灌瞎排，是加分项，但不是唯一标准。  
3. **过程是否健康 → `days≈112`、`T` 正常下降、损失偶发尖峰可忽略**。  
4. **单局 `R` / 某年 `year`**：方差大，不能拿一两行判断成败。  

每 100 局 Summary 里的 **`Δvs前100`**：近 100 均回报相对再前 100 的差；**前期多为正、后期接近 0** 较理想；长期大幅为负要警惕过拟合末段变差（届时仍以 `best` 权重做 1.3 评估）。

**注意：** 这些是**训练过程**信号。最终「比固定规则好不好」要等 **1.3** 的 `compare_summary`（灌排、雨利用率、`yield_factor` 等），不能只靠训练日志下结论。

#### `01_train/` 产物字段（文件级）

### 1.3 评估：怎么评、有哪些指标、和后面什么关系

**做法（不是再训练）：**

1. 表只用 **评估集**（`forecast_policy` / `actual_policy`），默认跑**全部验证年**。  
2. 两条臂共用同一套 `Irrigation.step` 水量递推，只换决策器：  
   - **PPO**：加载 `best`，掩码 argmax + 评估默认后处理（Hc 守卫、物理限幅等）  
   - **固定规则**：`<hmin` 灌到 `hmax`；超 `Hp`/`Hc` 则排；否则不动  
3. 逐日落盘 → 按年汇总 → PPO vs 规则多年均值与 Δ%。

**指标唯一计算入口：** `evaluation/metrics.py` 的 `compute_yearly_metrics`（一期评估、二期三方对比里的「任务指标」都走它）。

#### 年指标（`yearly_metrics_PPO.csv` / `_RULE.csv`）

| 字段 | 含义 | 偏好 |
|------|------|------|
| `year` | 验证年 | — |
| `rain_total` | 季内雨量合计 | 对照用 |
| `irrigation_total` | 灌水量合计 | 越低越好 |
| `drainage_total` | 排水量合计 | 越低越好 |
| `rain_utilization` | `(雨−排)/雨` | 越高越好 |
| `yield_factor` | 产量水分系数（按生育段 ks·ET 合成，∈[0,1]） | 越高越好 |
| `drought_risk_factor` | 与 `yield_factor` 同值（命名兼容） | 越高越好 |
| `managed_water` | 灌+排 | 越低越好 |
| `irrigation_times` / `drainage_times` | 灌/排**发生日数**（非连续段事件数） | 视情景 |
| `irrigation_small_run_2d_*` / `_ge3d_*` | 连续小额灌溉段（全日 0&lt;m≤20，≥2 / ≥3 d）的段数·天数·水量 | 论文机制；越低常更好 |
| `irrigation_topup_small_*` | 续灌段（首日 m&gt;20 + 后续小额） | 补充 |
| `drainage_small_run_*` | 连续小额排水段（与灌水分开） | 勿与「问题灌水」合并 |
| `stress_days` | 水分胁迫天（ks&lt;1 且 lamda&gt;0） | 越低越好 |
| `stress_days_all` | 胁迫天（不限 lamda） | 越低越好 |
| `overpond_days` / `_exposure` / `_events` | 超 Hc 天数 / 超深量 / 事件数 | 越低越好 |
| `max_consecutive_overpond_days` | 最长连续超淹 | 越低越好 |
| `max_h_end` | 季内最大日末水深 | 对照 |
| `no_drain_high_days` | 已≥Hc 却几乎未排的天数 | 越低越好 |

**五核心（论文/报告常画）：** 雨总量、灌总量、排总量、雨利用率、`yield_factor`。

#### `compare_summary.json`

- `ppo_*` / `rule_*`：上表各列的**多年均值**  
- `delta_pct`：相对规则的相对变化 %  
  - 越低越好的量：`(rule−ppo)/|rule|×100`（**正 = PPO 更省**）  
  - 越高越好的量：`(ppo−rule)/|rule|×100`（**正 = PPO 更好**）  
- `disagree`：逐日 PPO 与规则动作不一致的天数 / 比例（来自 `policy_compare_daily.csv`）

#### `02_eval/` 文件一览

| 文件 | 意义 |
|------|------|
| `policy_output_PPO.csv` / `_RULE.csv` | 逐日过程（水深、动作、雨、ET…） |
| `yearly_metrics_*.csv` | 上表年指标 |
| `compare_summary.json` | 多年对比 + Δ% + disagree |
| `policy_compare_daily.csv` | 逐日对齐；`disagree=1` 的日 = **二期审阅优先点** |
| `run_manifest.json` | 本评估产物路径清单 |

#### 这些指标后面共用吗？和 BC / 论文指标什么关系？

| 类别 | 是什么 | 和一期关系 |
|------|--------|------------|
| **任务/农艺指标**（灌排、雨利用率、`yield_factor`、超淹…） | `compute_yearly_metrics` | **一期 1.3 与二期 2.5 三方对比共用同一套**；seed 会把 `02_eval` 拷进会话，看板也可读 |
| **分歧日** | `policy_compare_daily` | 一期产出；二期 review 可标 `prefer_review`，引导专家先看 PPO≠规则的日子 |
| **BC 本身** | 监督微调（CE+KL）→ `ppo_hitl.pth` | **不是**上面农艺指标；BC 优化的是「跟专家标签」，不直接优化雨利用率 |
| **absorption / effort**（`07_metrics/`） | 改动复现率、确认保持率、人工工作量等 | **二期 HITL 专用论文辅助指标**，一期没有；与 `yearly_metrics` 互补，不替代 |

一句话：**农艺对比指标一期定稿、后面复用；BC 是另一条优化目标；absorption 只服务「人改了多少、模型学走了多少」。**

## 二期（`output/hitl_sessions/sess_<ts>/`）

**进入二期的门槛（一期须齐）：** `01_train/ppo_rice_best.pth` + `02_eval/compare_summary.json`（含 disagree）。  
本轮论文基础run：`output/runs/run_20261024_170858/`；`run_20261023_174121`保留为历史运行。

| STEP | 作用 | 过关标志 |
|------|------|----------|
| `2.1` | seed 整拷一期 | `ok: true`；回填 `SESSION_REL` |
| `2.2` | review 审阅表 | `03_review/current/review.csv` |
| `2.3` | resync（改动作后） | current更新，后续旧确认/旧专家动作失效；不新写history |
| 看板/CLI | 各审阅年定稿（无对应main STEP） | 整季实际审完并接受，生成trajectory_fingerprints |

`2.1` 的 `from_run`：填了 `RUN_REL` 则用该 run；否则自动选**最近带 best 的一期 run**。

### 二期要测什么（按 STEP）

先在 `main.py` 填：

```text
RUN_REL = "output/runs/run_20261024_170858"
MODEL_REL = ""   # 可空，会自动拼 …/01_train/ppo_rice_best.pth
SESSION_REL = "" # 2.1 跑完后再填
```

#### 2.1 seed — 导入一期进会话

- **测：** 是否把 `uploads` / `01_train` / `02_eval` 整拷进新 `sess_*`；`_workdir/model.pth` 存在。  
- **过关：** 返回 `ok: true`；会话内 `01_train/ppo_rice_best.pth` 存在；终端提示回填 `SESSION_REL`。  
- **失败常见原因：** `RUN_REL` 指错、该 run 无 best。

#### 2.2 review — 冻结 PPO 滚审阅表

- **测：** 评估集上按年 rollout；写出 `03_review/current/review.csv` + `original_trajectories/`（锁定）。  
- **过关：** 默认4个审阅年×112日=448行；`max-years`可缩短，须核对实际年份。有`a_model`/状态列，original锁定。
- **建议：** 可从分歧提示开始，但接受的单位是一整个生育季；2017—2020反馈留出年不用于反复改标签或选超参。

##### `review.csv` 列含义（一行 = 一天）

**改表时真正要用的（人工 HITL）：**

| 列 | 含义 | 是否改 |
|----|------|--------|
| `date` | 日期 `Y/M/D` | 不改（定位用） |
| `year` | 年 | 不改 |
| `prefer_review` | `1`=一期 PPO 与固定规则动作分歧日，优先审 | 不改（筛选用） |
| `editable` | `True` 才允许专家改；晒田/落干等固定规则日为 `False` | 不改 |
| `a_model` | 冻结PPO在当前审阅状态下的请求提案；resync会刷新后续日 | 不手改 |
| `a_expert` | 专家指定的合法请求；可编辑日初值为空，空值沿用当前PPO建议 | 通过看板选择，须在当日合法档内 |
| `confirmed` | 日级确认标记，不等于整季定稿 | 完整接受还需finalize及指纹 |

动作档须在 `-100…100`、步长 10（与 `ACTION_SPACE` 一致）。

**读懂状态 / 对照用（通常只看不改）：**

| 列 | 含义 |
|----|------|
| `step` | 本季内第几天（0 起） |
| `stage` | 生育阶段名 |
| `h_before` | 决策前田面水深 mm |
| `hmin` / `hmax` | 适宜水深上下限 |
| `Hp` / `Hc` | 排水触发 / 允许最大水深 |
| `lamda` | 产量敏感系数 |
| `ks` | 水分胁迫系数 |
| `P_cumu7` | 决策时可得的未来7日预报累计雨量（**含决策日** + 随后6日；与 `actual.P_1_a…P_7_a` 对齐） |
| `P_1_a` / `P_actual_display` | 实测雨用于环境水量平衡和事后评价；不写入人工审阅表，也不向专家审阅 API 返回 |
| `reason_code` | 结构化改因：`merge_small_irrigation` / `wait_forecast_rain` / `allow_low_water` / `other` |
| `reason` | 自由文本补充（可选） |
| `a_idx` | `a_model` 对应动作空间下标 |
| `a_applied` | 经守卫/限幅后**当日真正喂给 env** 的量 |
| `a_exec` | `env.step` 返回的执行量（与物理修正后一致） |
| `used_fixed_rule` | 当日走固定规则（晒田等） |
| `used_hc_guard` | 当日触发了 Hc 安全守卫 |
| `reward` | 该步环境奖励（训练回报分量，审阅次要） |
| `is_small_run` | 连续小额**灌溉**高亮（执行灌水量：全日小额≥2 d，或续灌后的小额日；排水不并入） |

**可忽略（体积大、改表易乱）：**

| 列 | 含义 |
|----|------|
| `prob_0`…`prob_20` | 掩码后 21 档动作概率（调试用） |
| `state_vec` | 8维状态向量；BC导出须与定稿轨迹逐日一致，不能用重算掩盖不一致 |

resync 后还可能多出：`needs_reconfirm`、`a_expert_hist`、`source` 等（后续日待再确认）。

**操作顺序：** 看板选择合法请求 → resync → 复核受影响后续日 → 整季接受并定稿。`review.json`通常优先于CSV，不要只改CSV后认为已更新主表。

#### 2.3 resync — 改动作后重推（人工环节）

- **测：** 至少改 **1 天** `a_expert`（或看板改表）→ 跑 resync → 该日之后水深与建议刷新；改日之前保留。  
- **过关：** `current/` 更新；若有 `needs_reconfirm` 则 T 之后可编辑日标出（不再写 `history/`）。  
- **验收（核心）：** 同状态、同请求动作（不论口头来自专家还是 PPO）→ 相同 ``a_exec`` 与下一状态（``apply_expert_action`` ≡ ``apply_action(fixed=False)``）。  
- **不测 resync 直接 BC：** 旧表若与「季初连续重放」不一致，BC **会被硬拦截**；须先 resync + 定稿。

#### 2.4 bc — 行为克隆微调

- **前置步骤：** 每年实际审完后，在看板点“本审阅年定稿”，或用`python run.py hitl finalize --work <新session路径> --year <审完年份> --source human`。定稿命令本身不替代人的判断。
- **测：** 定稿（含轨迹指纹）→ 季初连续重放 → parity 全过 → `labels.json` → `ppo_hitl.pth`。  
- **过关：** parity ``ok``；非法请求标签为 0；`n_include_bc`>0。有改动时看 `n_edited`>0。  
- **硬门槛：** `review_labels_parity.json` 失败则**禁止** BC（CLI/看板同一门槛）。  
- **标签：** BC 学合法**请求**档；执行量只用于递推/评价。``label_smoothing=0``。  
- **吸收率：** 主率排除掩码仅剩一档的强制日（另计 `n_forced_mask_only`）。  
- **看板：** BC 成功后自动跑 2.5；失败可手动对比。

#### 2.5 compare — 三方对比

- **测：** 规则 / 原 PPO / HITL 各跑评估 → `06_compare/` + `07_metrics/task_compare.json`（看板 BC 后自动触发亦可）。  
- **过关：** 三方齐全；核对多年/单年/反馈留出年范围。共享网络更新会改变留出年的决策，不能预设HITL应接近原PPO。
- **另：** `absorption.json`（含 `by_year`）/ `effort.json` 为论文辅助指标。

### 日常操作顺序

1. **已有论文结果：** 直接开看板选`sess_v3_candidate_feedback_20261025`；不需要重训或重新BC。
2. **新真人审阅：** 新session的`2.1`→`2.2`→改动作与`2.3`→各年实际审完并定稿→`2.4`→`2.5`。
3. **配置范围：** 默认40epoch的通用BC与论文160epoch上限、完整2016开发季等设置不同；详见交接手册第7节。
