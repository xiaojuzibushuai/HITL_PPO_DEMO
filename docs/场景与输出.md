# 情景、数据与输出（定稿）

## 0. 正式只认两大目录

```text
output/
├── runs/                    ★ 一期（可单独跑）
│   └── run_YYYYMMDD_HHMMSS/
│       ├── uploads/           ★ 原始训练集 / 评估集（面板上传或 scenario 快照）
│       │     forecast.csv / actual.csv
│       │     forecast_eval.csv / actual_eval.csv
│       │     growth_para.csv
│       ├── 01_train/          best/last + 训练曲线
│       └── 02_eval/           PPO vs 固定规则
│
└── hitl_sessions/           ★ 二期（与 Web 看板共用同一会话树）
    └── sess_YYYYMMDD_HHMMSS/
        ├── uploads/           ★ 同上原始表（seed 从 run 整拷 + scenario 补全）
        ├── 01_train/          ← seed 从 run 整拷
        ├── 02_eval/           ← seed 从 run 整拷（PPO vs 规则）
        ├── 03_review/         审阅工作台：锁定 original + 可改 current
        ├── 04_bc_export/       ★ BC 监督样本 labels.json（供 05_bc 微调；不是年指标）
        ├── 05_bc/             ★ 微调后的策略权重 ppo_hitl.pth（模型产物）
        ├── 06_compare/        ★ 三方各自再跑一整季评估的明细目录
        ├── 07_metrics/        ★ 论文汇总 JSON（吸收率/任务对比/耗时），不是模型
        └── _workdir/          运行时拷贝（env chdir；≠ uploads 溯源原件）
```

| 问题 | 答案 |
|---|---|
| 原始训练/评估表放哪？ | **`uploads/`**；面板上传或 pipeline 快照 scenario |
| `_workdir` 是什么？ | 环境运行用临时拷贝；论文溯源看 `uploads/` |
| 二期含一期产物吗？ | **是**，`seed` 整拷 `uploads`+`01_train`+`02_eval` |
| **CLI 是什么？** | 命令行：在 `PPO_Rice_Env/` 下执行 `python run.py hitl <子命令>`。与 Web 看板调用**同一套** `hitl.pipeline` / `api.hitl_*`，只是入口不同（终端 vs 浏览器按钮） |
| `04`/`05`/`06`/`07` 差在哪？ | 见下方专节 |

### `04`～`07` 一眼区别

| 目录 | 一句话 | 你什么时候看 |
|---|---|---|
| **`04_bc_export/`** | BC 用监督样本目录（原名 export）：定稿后的**逐日标签**（状态→动作），供后续 `05_bc` 微调 | 核对「学了哪些天、专家改没改」 |
| **`05_bc/`** | **微调后的策略文件** `ppo_hitl.pth`（+训练摘要） | 要部署/再评估 HITL 策略 |
| **`06_compare/`** | 规则 / 原PPO / HITL **各自独立跑季**的原始评估表 | 要对比三方灌排/产量等任务表现明细 |
| **`07_metrics/`** | 从审阅表+三方结果**汇总**出的论文用 JSON | 写论文表格：吸收率、耗时、任务对比摘要 |

它们不是「同一指标的四个副本」：`04`=监督数据，`05`=模型，`06`=三方评估明细，`07`=汇总指标。

## 1. 入口怎么选 + 二期怎么跑

| 入口 | 干什么 | 何时用 |
|---|---|---|
| **`api.py`** | 函数库（`pipeline` / `hitl_*` / `dispatch`） | 被其它入口调用；写脚本 `from api import …` |
| **`main.py`** | 改 `METHOD=` 调用 `api.dispatch` | 本地点一下测某一模块；**默认 `hitl_board` 开网页** |
| **`run.py`** | argparse 命令行 | 文档复制命令、CI、带很多 flag |

三者**不重复实现算法**，都落到同一套 `api` / `hitl.pipeline`。

**一键开 Web 测全流程：**

```bash
cd PPO_Rice_Env
python main.py
# 等同: python run.py hitl board
# 浏览器: http://127.0.0.1:5050
```

**CLI** = 不用浏览器时敲命令。均在 `PPO_Rice_Env/` 下执行。

### 1.1 推荐操作流程（有人工审阅）

```text
① 一期已完成 → 有 output/runs/run_<ts>/{uploads,01_train,02_eval}

② seed     新建 sess，把一期整拷进来
③ review   冻结原 PPO 滚季 → 03_review/current + 锁定 original
④ 人工     看板按规范审阅年逐年改 a_expert / 确认（留出年不进下拉）
⑤ resync   按专家动作重推水深，刷新建议（original 不动）；无改动勿空跑
⑥ 循环 ④⑤：上游动作变更后逐日认可当前重推建议或指定专家动作；各规范审阅年定稿时不得有 needs_reconfirm，且至少有一个有效专家改动
⑦ bc       → 须 bc_ready；写 04_bc_export/labels.json + 05_bc/ppo_hitl.pth
⑧ compare  → 06_compare/{rule,original_ppo,hitl_ppo} + 07_metrics/*

专家审阅看板降雨图 = 决策时可用的未来7日预报累计量 P_cumu7；当日实测 P_1_a 仅用于环境递推和事后评价（见 docs/WEB_HITL.md）。
```

### 1.2 对应命令（复制即用）

```bash
# 指定一期 run（省略 --from-run 则用最近一次 run）
python run.py hitl seed --from-run output/runs/run_YYYYMMDD_HHMMSS

# 生成审阅表（快速试跑可加 --max-years 1）
python run.py hitl review --max-years 1
# 或打开看板改动作（推荐）：python run.py hitl board  → http://127.0.0.1:5050

# 改完后重推（CLI 读 current 表；看板点「resync」）
python run.py hitl resync

# 定稿 → labels + ppo_hitl
python run.py hitl bc

# 三方自主评估
python run.py hitl compare
```

可选：`--work output/hitl_sessions/sess_…` 指定会话；默认用**最近**一个 `sess_*`。

**一键无人工**（仅试通路；未改动作时 BC 样本几乎全是「原样确认」）：

```bash
python run.py hitl pipeline --max-years 1 --skip-bc   # 只到 review
python run.py hitl pipeline --max-years 1             # seed→review→bc（仍无专家改动）
```

编程入口（推荐）：改 `main.py` 顶部 `METHOD` / `KW` 后 `python main.py`。  
等价：`from api import dispatch` → `dispatch("hitl_review", max_years=1)`。

### 1.3 看板 vs CLI

| 你想做的事 | CLI | 看板按钮 |
|---|---|---|
| 导入一期 | `hitl seed` | seed 导入 / 一期训练后自动 seed |
| 生成审阅 | `hitl review` | 生成 review |
| 改动作+理由 | 改 `03_review/current/*.json` | 表格里改 |
| 重推 | `hitl resync` | resync |
| 微调 | `hitl bc` | BC |
| 三方对比 | `hitl compare` | 三方对比 |

### 看指标 → 打开哪个文件（看板摘要同源）

| 你想看 | 文件 | 关键列 / 字段 |
|--------|------|----------------|
| 训练是否收敛（回报/动作） | `01_train/training_log_*.csv` | `episode`, `return`, `mean_return`, `action_count` |
| 训练损失 | `01_train/training_loss_*.csv` | `policy_loss`, `value_loss`, `entropy_loss` |
| 多年均值 KPI、相对规则 Δ% | `02_eval/compare_summary.json` | `ppo_*` / `rule_*` / `delta_pct`：雨利用率、灌/排总量、管理水量、产量系数 |
| 某一年 KPI | `02_eval/yearly_metrics_PPO.csv`（及 `_RULE`） | `year`, `rain_utilization`, `irrigation_total`, `drainage_total`, `managed_water`, `yield_factor`, 灌排次数 |
| 某一年整季水深/动作轨迹 | `02_eval/policy_output_PPO.csv` | `date`, `h_before`, `h_after`, `a_mm`, `a_exec`, `m`, `d` |
| 哪些天 PPO 与规则分歧 | `02_eval/policy_compare_daily.csv` | `date`, `a_ppo`, `a_rule`, `disagree` |
| 用哪个权重做评估/审阅 | `01_train/ppo_rice_best.pth` | —（不要用 last 做正式对比） |

### 逐日列（评估 `policy_output_*.csv`）

`date, episode, step, h_before, h_after, hmin, hmax, Hp, Hc, lamda, ks, P_cumu7, a_cmd, a_mm, a_exec, m, d, P_1_a, et0_a, reward_total`

### 年指标（`yearly_metrics_*.csv`）

**看板 / 论文主表（五核心 + 日数）：** `rain_utilization`, `irrigation_total`, `drainage_total`, `managed_water`, `yield_factor`, `irrigation_times`, `drainage_times`  
（`irrigation_times`/`drainage_times` = **有灌/排发生的日数**，不是连续操作段数。）

**连续小额 / 操作段（`evaluation/operation_runs.py`，写入同年 CSV）：**  
`irrigation_operation_days`, `irrigation_contiguous_segments`,  
`irrigation_small_run_2d_*` / `irrigation_small_run_ge3d_*`（段数/天数/水量），  
`irrigation_topup_small_*`（续灌：首日 m>20 + 后续小额），  
`drainage_small_run_2d_*` / `drainage_small_run_ge3d_*`（排水单独，不与灌水合并）。

**仍写入 CSV、看板主表不强调：** `stress_days*`, `overpond_*`, `max_h_end`, `no_drain_high_days`（扩展诊断）

## 3. 二期 `04`～`07`：文件、字段、怎么用

打开一个 `sess_*` 即可离线分析。`meta.json` 的 `run_id` 指向来源一期 run。

### 3.1 `03_review/`（审阅工作台，bc 之前主要看这里）

| 路径 | 作用 |
|---|---|
| `original_trajectories/` | **锁定**的首次 rollout；resync/改动作都不动它（改前对照） |
| `current/` | 专家当前表（含 `a_expert` / `confirmed` / `reason_code` / `reason`）；看板读写这里 |
| `edits_log.jsonl` | 每次保存/确认的追加日志 |
| `history/` | 旧版残留；现行回退用 `original_trajectories/` |

### 3.2 `04_bc_export/labels.json`（BC 监督样本 / bc_export）

**目录含义：** `04_bc_export` = 给 **Behavior Cloning 微调**准备的导出，不是泛化「任意导出」。  
**何时产生：** `python run.py hitl bc`（或看板 BC）——先写本目录，再写 `05_bc/`。  
**是什么：** 按专家最终动作**固定重放**后的逐日样本数组（JSON records）。  
**用途：** ① `05_bc` 微调的训练集；② 论文里展示「专家改了哪些天」。  
**不是：** 年指标、也不是模型权重。

| 字段 | 含义 |
|---|---|
| `date` / `year` / `stage` | 日历与生育期 |
| `h_before` / `h_after` | 当日初/末日水深（重放一致后） |
| `s_vec` | 状态向量（BC 输入） |
| `a_model` | 定稿时表内模型建议 mm |
| `a_expert` | 专家最终动作 mm（监督目标） |
| `a_idx` | `a_expert` 在动作空间中的离散下标（BC 分类标签） |
| `a_actual` | 环境实际执行 mm（可能被边界裁剪） |
| `flag` / `weight_type` | `confirmed` 确认原样 / `edited` 改过 / `fixed_rule` 固定规则日等 |
| `confirmed` | 是否已确认（BC 默认只学 confirmed） |
| `editable` | 该日是否允许专家改 |
| `include_in_bc` | **是否进入 BC**（固定规则日通常为 false） |
| `boundary_break` | 专家意图与实际执行因边界不一致 |
| `used_hc_guard` / `used_fixed_rule` | 是否触发护栏 / 固定规则 |

过滤进 BC：`include_in_bc == true`（见 `hitl/recompute.to_bc_arrays`）。

**计数易混：** `n_labels` = 导出行总数（含晒田等）；`n_include_bc` = 真正进训天数（定稿可编辑日）；`n_edited` = 其中专家≠模型的天数（权重 `w_edit`）。**不是只训改动日**，而是整季确认日 + 改动加权。

### 3.3 `05_bc/`（微调后的策略）

| 文件 | 作用 |
|---|---|
| `ppo_hitl.pth` | HITL 策略权重（后续 compare / 部署用这个） |
| `ppo_hitl_config.json`（侧车） | 与权重配套的网络配置 |
| `hitl_result.json` | 本次 BC 摘要：`n_labels`、`n_include_bc`、`n_edited`、`best_epoch`、路径 |

**怎么用：** `compare` 自动读 `ppo_hitl.pth`；或自己拿去 `api.evaluate(hitl_path, …)`。

### 3.4 `06_compare/`（三方任务评估明细）

**何时产生：** `python run.py hitl compare`。  
**结构：**

```text
06_compare/
  rule/           固定规则整季评估（同 02_eval 那套 CSV/JSON）
  original_ppo/   原 best 权重再跑评估
  hitl_ppo/       ppo_hitl 再跑评估
  three_way.json  三臂目录索引 + 指向 07_metrics/task_compare.json
```

每臂内常见：`policy_output_*.csv`、`yearly_metrics_*.csv`、`compare_summary.json`。  
**用途：** 画三方对比图、查某年灌溉量/雨水资源利用率等；**不是** labels。

### 3.5 `07_metrics/`（论文汇总，不是模型）

| 文件 | 何时写 | 关键字段 / 怎么用 |
|---|---|---|
| **`absorption.json`** | bc / compare 后自动；看板「吸收率」可重算 | 见下表 |
| **`effort.json`** | seed/review/resync/bc/compare 各阶段墙钟自动追加 | `stages[].stage/seconds`；`total_seconds` → 审阅投入 |
| **`task_compare.json`** | compare 后 | 三臂 `yearly_metrics` 路径 + 各臂 `compare_summary` 摘要 |

**`absorption.json` 字段注释：**

| 字段 | 含义 |
|---|---|
| `n_days` / `n_confirmed` | 审阅总天数 / 已确认天数 |
| `n_edited_among_confirmed` | 确认里相对表内 `a_model` **改过**的天数 |
| `n_keep_among_confirmed` | 确认里与 `a_model` **一致**的天数 |
| `confirm_keep_rate` | 确认样本中「原样确认」占比 |
| `edit_share_among_confirmed` | 确认样本中「改动」占比 |
| `n_edit_vs_original_traj` | 相对 **original 锁定轨迹** 改动的确认天数 |
| `edit_reproduce_rate` | 改动日且可选档>1：掩码后 argmax 复现率；强制单档日见 `n_forced_mask_only` |
| `confirm_hold_rate_policy` | HITL 对「未改日」仍输出标签的保持率 |
| `by_year` | 按审阅年拆分的同上两率；看板对比视图切年时用 |
| `note` | 失败/仅样本统计时的说明 |

无 `ppo_hitl` 时率为 `null`，仍可看确认/改动占比。复现率低 ≠ 训练失败（CE 可降、KL 仍保守）；留出验证年单表 HITL≈原 PPO 属预期。

## 4. 输入（`configs/scenario.json` → `data`）

## 5. 各模块单独跑 → 落盘清单

### 5.1 一期 CLI / `api`

| 操作 | 根目录 | 写出文件 |
|---|---|---|
| `run.py pipeline`（默认） | `runs/run_<ts>/` | `uploads/`（scenario 表快照）+ 下两行 |
| `train`（写入 `01_train/`） | 同上或 `--save-dir` | `ppo_rice_best.pth` + `*_config.json`；`ppo_rice_last.pth` + config；`training_log_<ts>.csv`；`training_report_<ts>.json`；`training_results_<ts>.png`；`meta.json`（pipeline 时） |
| `eval`（写入 `02_eval/`） | 同上或 `--out-dir` | `policy_output_PPO.csv`；`yearly_metrics_PPO.csv`；`policy_output_RULE.csv`；`yearly_metrics_RULE.csv`；`compare_summary.json`；`policy_compare_daily.csv`；`run_manifest.json`；`_workdir/`（forecast/actual 拷贝） |

单独 `train` / `eval` 省略目录时也会新建 `runs/run_*`。详见 `docs/WEB_HITL.md`。

### 5.2 二期 CLI（`python run.py hitl …`）

| 命令 | 会话内位置 | 写出 / 更新 |
|---|---|---|
| `hitl seed [--from-run …]` | `sess_<ts>/` | 整拷 `uploads`+`01_train`+`02_eval`；scenario 补全 uploads；`01_train/seed_report.json`；`_workdir` |
| `hitl review [--max-years N]` | `03_review/` | `current/*`；锁定 `original_trajectories/` |
| `hitl resync` | `03_review/` | 更新 `current/`（含 `reason_code`） |
| `hitl finalize --work … [--year Y]` | `meta.json` + `current/` | 定稿指纹；`feedback_source` |
| `hitl bc [--epochs N]` | **`04_bc_export/`** + **`05_bc/`** | `labels.json`；`ppo_hitl.pth`；`hitl_result.json`；并写 **`07_metrics/absorption.json`** |
| `hitl compare` | **`06_compare/`** + **`07_metrics/`** | 三臂 eval；`three_way.json`；`task_compare.json`；`expert_rationale_audit.json`；刷新 absorption |
| `hitl board` | 读写当前/最近 `sess_*` | 浏览器编排上述步骤（不另起算法） |

字段注释见 **§3**。

### 5.3 Web 看板（与 CLI 同目录）

完整路由表见 **`docs/WEB_HITL.md`**。一期可用看板「一期训练+评估」或 CLI `pipeline`；二期 seed→review→resync→bc→compare 看板与 CLI 共用 `hitl_sessions/`。

## 6. 论文指标 ↔ 现有文件

| 论文问题 | 看哪个文件 |
|---|---|
| 专家定稿了哪些 (s,a)？ | `04_bc_export/labels.json`（筛 `include_in_bc` / `flag==edited`） |
| 专家为何改（等雨/偏干/合并小额）？ | `03_review/current` 的 `reason_code`；事后 `07_metrics/expert_rationale_audit.json`（三项分列，无合成成功率） |
| 是否减少连续小额灌？ | 各臂 `yearly_metrics_*.csv` 的 `irrigation_small_run_*` / `irrigation_topup_small_*`（执行量口径） |
